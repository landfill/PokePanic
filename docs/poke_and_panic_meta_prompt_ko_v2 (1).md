# 똥침각 / POKE & PANIC — 웹 게임 제작 메타 프롬프트

> 개정 2 · 2026-09-11 · 실패 중심 코미디 설계 반영  
> 이전 버전을 대체하는 전체 제작 명세. 이 문서만으로 구현할 수 있도록 시나리오·규칙·기술·검증 기준을 통합한다.

## 1. 역할과 최종 목표

당신은 캐주얼 게임 디렉터, Three.js 개발자, 테크니컬 아티스트, 캐릭터 애니메이터, 모바일 웹 성능 엔지니어다.

Three.js와 SVG를 중심으로, 짧은 타이밍 조작과 정체 공개의 반전이 결합된 코미디 아케이드 웹 게임을 실제 실행 가능한 프로젝트로 제작하라. 기획 설명이나 정적인 목업으로 끝내지 말고, 시작부터 게임오버와 재도전까지 이어지는 플레이 루프를 완성하라.

게임명은 한국어 `똥침각`, 영어 `POKE & PANIC`을 사용한다. 핵심 경험은 **“성공하려고 진지하게 조작하지만, 실패하는 순간에도 다음 장면이 궁금한 게임”**이다.

`타이밍 조작 → 접촉 또는 헛손질 → 숨겨진 정체 공개 → 성공의 손맛 또는 실패의 반전 → 즉시 재도전`

### 게임 디자인의 고정 원칙

| 영역 | 제작 원칙 |
|---|---|
| 성공의 보상 | 정확히 맞힌 손맛, 점수와 연속 성공 기록, 다음 상대 진입 |
| 실패의 보상 | 실패 방식에 맞는 반전, 캐릭터의 예상 밖 반응, 새로운 결말 발견 |
| 판정의 공정성 | 동일한 입력·배치에는 동일한 점수. 모든 캐릭터의 성공 기준은 700점 |
| 숨겨진 정보 | 정체와 반응은 숨기되 캐릭터별 비밀 성공 조건은 만들지 않음 |
| 플레이 구조 | 탭 두 번, 상대당 한 번 발사, 한 번 실패하면 게임오버 |
| 재도전 | 이번 판 점수는 초기화하되 발견·감상 기록과 등장 순서는 유지 |

**실패 연출은 패배를 설명하는 부가 영상이 아니라 주력 콘텐츠다.** 성공 공략의 복잡성을 늘리는 대신, 실제 조작이 실패의 모양과 코미디 장면에 연결되도록 설계하라. 단순히 0%에서 눌러 같은 영상을 반복해서 뽑는 구조도 피한다.

초기 버전에 라이프, 부활, 도주 성공에 의한 런 연장, 캐릭터별 숨겨진 유효 파워대, 정체를 맞히는 추리 시스템을 추가하지 않는다. 개발 편의를 이유로 실패 원인과 무관한 영상 하나를 모든 상황에 재생해서는 안 된다.

아래의 시간·용량·성능·난이도 수치는 초기 설계 목표다. 실측 없이 달성했다고 주장하지 말고, 조작 감각과 실패 후 재도전 경험을 검증하면서 설정 파일에서 조정할 수 있게 하라.

## 2. 세계관과 표현 범위

무대는 현실 도시를 장난감 세트처럼 재구성한 가상의 코미디 쇼 촬영장이다. 화면 속 인물은 모두 자발적으로 쇼에 참가한 20세 이상 성인 배우이며, 성별·연령대·성격·직업은 정체 공개 전까지 숨겨진다. 경찰과 체포도 쇼 안의 연출이다.

플레이어는 양손을 모은 똥침 포즈를 본뜬 둥근 폼 장갑 소품으로 타이밍 미션에 도전한다. 접촉 대상은 바지 바깥에 부착된 보호패드다. 노출·관통·혈액·배설물·성적 연출·현실적인 부상 묘사는 사용하지 않는다. 카메라의 관심은 신체 감상이 아니라 조준, 표정, 반전, 소품 사고에 둔다.

대사와 웃음의 대상은 상대의 성별이나 외모가 아니라, 앞을 확인하지 않고 도전한 플레이어의 무모함이다. 시작 화면 하단에는 “성인 배우들의 만화적 슬랩스틱입니다. 실제로 따라 하지 마세요.”라는 짧은 안내를 배치하라.

### 오프닝

네온 간판이 한 번 깜빡이고 화면 아래에서 폼 장갑을 낀 양손이 비장하게 결합한다. 거창한 승부를 예고하는 짧은 음악이 흐르지만, 카메라 앞에는 누군지 모를 참가자의 바지 뒷부분만 보인다.

화면 문구는 “각은 봤고, 앞은 못 봤다.”다. 설명은 길게 하지 않는다. 첫 조작 안내는 “한 번 눌러 파워, 한 번 더 눌러 각도.”로 끝낸다.

## 3. 화면 구도와 기본 플레이 루프

조준 단계에서는 상대의 **허리선부터 엉덩이 아래까지의 옷 입은 뒷모습**만 보여라. 얼굴·머리·가슴·발·이름·직업은 노출하지 않는다. 그림자, 반사, 화면 가장자리의 액세서리로 정체가 먼저 드러나지 않게 하라.

상대는 처음부터 완전한 전신 캐릭터로 존재해야 한다. 후면 이미지를 띄웠다가 무관한 전면 이미지로 교체하는 방식은 금지한다. 같은 캐릭터가 카메라 후퇴와 몸 회전으로 정체를 공개해야 한다. 조준 전후에 바지 색, 체형 연결부, 소품 위치가 달라지면 안 된다.

문서에서 **라운드**는 상대 한 명에 대한 도전, **한 판 또는 런**은 새 게임부터 첫 실패까지의 진행, **누적 발견 기록**은 여러 판에 걸쳐 유지되는 기록을 뜻한다.

한 라운드의 흐름은 다음과 같다.

`등장 → 파워 선택 → 각도 선택과 자동 발사 → 접촉/빗나감 → 판정 점수 표시 → 전신·앞모습 공개 → 성공 또는 실패 연출 → 다음 라운드 또는 게임오버`

한 상대에게 발사 기회는 한 번이다. 성공하면 누적 점수와 연속 성공 수가 증가하고 다음 상대가 등장한다. 실패하면 실제 실패 원인에 맞는 장면이 재생된 후 해당 판이 끝난다. 실패 연출이 끝났다고 라이프를 차감하고 이어 가거나, 무효 처리하고 재발사하게 만들지 않는다.

성공 라운드는 약 8~12초의 전체 템포, 실패 장면의 본편은 정체 공개 후 약 3~5초를 출발점으로 삼는다. 이는 연출 목표이며 사용자의 입력 대기시간을 강제로 제한하는 규칙이 아니다.

게임오버 뒤에는 한 번의 재도전 입력으로 새 상대에게 진입한다. 메뉴, 타이틀, 장황한 오프닝, 매번 반복되는 튜토리얼을 거치지 않는다. 이전 상대가 첫 상대로 고정 반복되지 않도록 등장 관리를 판과 분리한다.

**낮은 파워로 성공 가능성이 사라졌더라도 각도 단계를 생략하지 않는다.** 약하게 맞히는 것과 옆으로 빗나가는 것이 다른 실패 장면으로 이어져야 한다. 승패뿐 아니라 실패의 모양도 두 번째 조작의 결과다.

## 4. 조작: 두 번의 입력으로 끝나는 타이밍 게임

### 파워 선택과 성공 가능 구간

가로형 게이지 안에서 커서가 0~100 사이를 좌우 왕복한다. 첫 번째 탭으로 현재 파워를 고정한다. 숫자, 커서 위치, 소리, 구간 강조가 서로 일치해야 한다.

게이지는 누르고 충전하는 방식이 아니다. 자동 왕복하는 커서를 타이밍에 맞춰 멈추는 방식이다. 높은 파워를 정확히 고르는 타이밍 조작으로 설계하고, 전략성을 억지로 추가하기 위해 고파워에 임의의 실패 확률을 붙이지 않는다.

현재 점수식에서 정중앙 명중 기준 성공 가능한 파워는 약 72.3%부터다. 게이지에 **“정중앙 기준 성공 가능”** 경계와 낮은 파워 구간의 구분을 표시한다. 해당 경계를 넘었다고 무조건 성공하는 것처럼 초록색 ‘성공 확정’ 안내를 하지 않는다.

정확한 가능 여부는 표시용 반올림 수치가 아니라 `maxRawScore = round(1000 × P^1.1)`와 성공 기준의 비교로 결정한다. 약 72.3%라는 설명과 실제 점수의 반올림 경계는 구분한다. 경계·경고·최대 점수는 5장의 공통 계산 함수를 사용하고 별도 하드코딩하지 않는다.

파워 고정 뒤에는 `정중앙 명중 시 최대 570점 / 성공 기준 700점`처럼 현재 파워로 가능한 최대 점수를 짧게 표시한다. 성공 불가능 구간에서는 `파워 부족 · 그래도 방향은 정하세요`처럼 원인을 알려주되 조작을 막거나 실패 장면을 미리 공개하지 않는다.

색상만으로 구간을 구분하지 말고 눈금과 패턴도 제공한다. 작은 모바일 화면에서 모든 설명을 상시 노출하지 말고 경계 눈금과 고정 직후의 한 줄 안내로 전달한다.

### 각도 선택과 발사

파워가 고정된 뒤 각도 조작을 활성화한다. 정면을 0도로 하여 **좌우 -60도~+60도, 총 120도** 범위에서 방향 포인터가 왕복한다. 여기서 각도는 상하 발사각이 아니라 수평 방향각이다.

두 번째 탭으로 각도를 고정하고 즉시 발사한다. 별도의 세 번째 발사 버튼은 만들지 않는다. SVG 부채꼴 계기판, 화면 속 방향 가이드, 3D 장갑의 방향이 같은 값을 사용해야 한다.

첫 라운드의 왕복 주기는 파워 약 2.2초, 각도 약 3초를 출발점으로 삼는다. 왕복 주기는 한쪽 끝에서 반대쪽 끝을 거쳐 돌아오는 전체 시간이며, 반드시 기다려야 하는 시간이 아니다. 각도 단계 진입 후 유효한 새 입력으로 즉시 멈출 수 있다.

난이도가 올라가도 파워 1.2초, 각도 1.7초보다 빨라지지 않게 초기 제한을 둔다. 속도는 라운드 사이에만 바꾸고 선택 중 갑자기 가속하지 않는다.

### 정답 방향의 작은 변주

첫 라운드는 중앙 배치를 사용해 조작을 익히게 한다. 이후에는 상대를 화면 안에서 조금씩 좌우로 배치해 정답 방향이 늘 0도가 되지 않도록 한다. 목표 중심 방향의 초기 범위는 약 -12도~+12도로 두고 화면 구성과 실제 유효 명중 폭을 보며 조정한다.

화면 좌표를 가짜로 바꾸는 것이 아니라 발사 원점에 대한 상대·보호패드의 실제 월드 좌표를 바꾼다. 카메라가 상대를 따라가더라도 계기판과 조준 가이드는 실제 상대 방향을 반영해야 한다. 시각적으로 다른 위치인데 계산상 정답은 항상 0도인 구현을 금지한다.

배치는 조작 시작 전에 확정하고 발사·판정까지 고정한다. 초기 버전에서 조준 중 갑작스러운 회피, 정체에 따른 비밀 판정 크기, 보이지 않는 좌우 보정을 사용하지 않는다. 모든 캐릭터에 같은 크기와 높이의 판정 패드를 적용하고, 수평 조작만으로 도달할 수 있도록 발사 높이를 맞춘다.

캐릭터의 체형과 뒷모습 구도는 유지하되 360px 너비에서도 패드와 손 소품이 가려지지 않게 배치 범위를 제한한다. 실제 거리와 패드 크기로 유효 각도를 계산하고, 과도하게 좁은 판정 폭은 플레이 테스트에서 조정한다.

### 입력 처리

모바일은 큰 하단 버튼의 탭, 데스크톱은 같은 버튼의 클릭 및 Space/Enter를 지원하라. 버튼 문구는 상태에 따라 “파워 결정”과 “각도 결정 · 발사”로 바뀐다.

터치와 마우스는 Pointer Events 중심으로 통합하라. 한 번의 조작이 pointerdown, click, 키보드 기본 동작 등으로 중복 처리되지 않게 하라. 각도 확정에는 첫 입력이 해제된 뒤의 새로운 입력이 필요하다. 키 반복, 멀티터치도 방어하되 정상적인 빠른 두 번 입력을 불필요하게 지연시키지 않는다. 설정과 언어 버튼 입력이 발사로 전파되어서는 안 된다.

왕복 운동은 프레임당 위치 증가가 아니라 일시정지 시간을 제외한 공통 게임 시계의 함수로 계산하라. 입력 순간에도 같은 함수를 호출해 값을 확정한다. 30/60/120fps에서 같은 게임 시각의 입력이면 같은 결과가 나와야 한다.

## 5. 명중 판정과 점수

### 변하지 않는 판정 규칙

**점수는 파워와 실제 명중 위치로 결정한다. 랜덤 숫자를 점수에 더하거나 빼지 않는다.** 상대의 정체·성별·성격·발견 기록은 점수에 영향을 주지 않는다. 모든 캐릭터의 쓰러짐 기준은 **700점**이며 발사 전에 표시한다.

발사 시점에 파워, 각도, 발사 원점, 보호패드의 위치·크기·변환을 불변 데이터로 저장한다. 이후 판정이 끝날 때까지 보호패드의 판정 위치를 유지한다. 캐릭터의 호흡 애니메이션 때문에 이미 정한 결과가 바뀌면 안 된다.

발사 방향과 보호패드의 접점을 계산하고, 화면 속 장갑도 그 경로를 따라 이동시켜라. 양손 소품의 둥근 끝점을 접촉 기준으로 사용한다. 명중했다면 패드 표면에서 멈추고 반동을 준다. 빗나갔다면 같은 경로로 옆을 지나가야 하며, 명중 이펙트를 출력해서는 안 된다.

정규화된 타원형 보호패드를 기준으로 다음 점수식을 사용한다. `round`는 음수가 아닌 값에서 0.5 이상을 올리는 반올림이며 구현·테스트·UI에서 같은 함수를 사용한다.

```text
P = clamp(확정 파워 / 100, 0, 1)
u = 패드 로컬 좌표에서 접점의 가로 중심 오차 / 패드 가로 반경
v = 패드 로컬 좌표에서 접점의 세로 중심 오차 / 패드 세로 반경
d = sqrt(u*u + v*v)

패드와 접촉하지 않거나 d >= 1이면:
    accuracy = 0
    rawScore = 0
그 외에는:
    accuracy = clamp(1 - d*d, 0, 1)
    rawScore = round(1000 * P^1.1 * accuracy^1.6)

maxRawScore = round(1000 * P^1.1)
canStillSucceed = maxRawScore >= 700
isSuccess = rawScore >= 700
```

파워는 장갑의 이동 속도, 접촉 연출 강도, 점수에 영향을 준다. 낮은 파워라는 이유로 보이지 않는 거리 보정을 추가하지 않는다. 극저파워에서도 선택한 각도에 따라 짧고 힘없는 소품 동작을 수행하고, 명중·빗나감 및 결과 연출을 일치시킨다. 0%에서는 힘없는 접촉 동작을 하더라도 패드 변형과 유효 타격은 없으며 점수는 0점이다. 성공 구간 안내의 최대 점수는 파워 부족을 설명하기 위한 상한이지 실제 명중 점수가 아니다.

### 판정과 연출을 분리

| 판정 점수 | 결과 | 연출 방향 |
|---|---|---|
| 900~1,000 | 대성공 | 캐릭터 고유 반응, 정체 공개 후 확실한 균형 상실 |
| 700~899 | 성공 | 짧은 고유 리액션과 주저앉음, 다음 라운드 |
| 650~699 | 아슬아슬한 실패 | 쓰러질 듯하다가 버티는 등 성급한 안도를 뒤집는 연출 |
| 0~649 | 실패 | 접촉 여부·파워·명중 오차에 따른 실패 연출 |

650점은 실패 연출을 구분하기 위한 초기값이며 성공 기준은 아니다. 설정을 바꿔도 700점 이상의 성공을 반격·체포로 뒤집어서는 안 된다. 실패 영상을 보여주기 위해 명중 점수를 낮추거나 성공 캐릭터를 바꾸지 않는다.

성공한 라운드에만 누적 점수를 지급한다. 해당 라운드를 포함한 연속 성공 수를 기준으로 콤보 배수 `min(1 + 0.1 × (연속 성공 수 - 1), 2)`를 적용한다. 획득 점수는 `round(rawScore × 콤보 배수)`이며 성공 여부는 배수 적용 전 rawScore로 판단한다.

화면에는 “판정 점수”와 “콤보 포함 획득 점수”를 구분한다. 실패에는 점수를 추가하지 않지만 새로운 결말의 발견 기록은 남는다. 결말 발견 자체에 점수나 콤보를 지급하지 않는다.

### 이해 가능한 결과 피드백

`파워 82% · 정확도 90% · 판정 679점 · 성공 기준까지 21점 부족`처럼 실제 계산값을 사용한다. 정확도는 위 accuracy의 백분율이며 부족분은 rawScore로 계산한다. 파워 부족, 명중 오차, 빗나감을 혼동하지 않도록 6장의 실패 분류를 함께 사용한다.

파워 60%의 정중앙 최대 점수는 570점, 70%는 675점, 75%는 729점, 100%는 1,000점이다. 설명용 예시는 공통 함수로 검증하고, 경계 근처에서는 표시용 파워의 자릿수 때문에 성공 가능 여부가 모순되어 보이지 않게 한다.

## 6. 정체가 숨겨진 캐릭터와 실패 연출 시스템

### 캐릭터와 판정의 분리

라운드 시작 시 캐릭터와 의상·배치를 확정한다. 실패한 뒤 불리한 인물을 새로 뽑는 방식은 금지한다. 캐릭터는 처음부터 존재하고 정체 공개 여부만 상태로 관리한다.

최소 8개의 캐릭터 원형을 구현한다. 얼굴, 상체 실루엣, 자세, 소품, 반응 타이밍으로 구분하고 모든 인물이 명확한 성인으로 보이게 한다. 캐릭터 차이는 공략법이 아니라 반응과 코미디의 차이다.

| 캐릭터 | 정체 공개 시 특징·성격 | 대표 실패 반응 | 짧은 성공 반응 |
|---|---|---|---|
| 철근 씨 | 거대한 어깨의 성인 남성, 작은 운동 가방, 다혈질 | 플레이어를 붙잡고 만화식 난투 | 거대한 상체가 천천히 주저앉고 작은 가방만 한 박자 늦게 떨어짐 |
| 민원 여왕 | 단정한 차림의 성인 여성, 휴대전화, 냉정·원칙주의 | 버튼 한 번으로 경찰 등장, 수갑 연행 | 넘어지면서도 휴대전화 화면은 끝까지 수평으로 유지 |
| 퇴근 전 팀장 | 피곤한 중년 남성, 구겨진 셔츠, 인내심 바닥 | 소매를 걷자 플레이어가 먼저 주저앉음 | 주저앉는 동시에 손목시계를 보고 퇴근 표정 |
| 액션 배우 | 운동복 차림의 성인 여성, 촬영용 배지, 승부욕 강함 | 실패 접촉 뒤 돌아오는 장갑을 잡아 플레이어를 소품처럼 회전시킴 | 안전 매트로 굴러 착지한 뒤 누운 채 엄지를 올림 |
| 요가 고수 | 유연한 성인 남성, 차분함 | 반동으로 돌아오는 장갑을 잡아 엉킨 자세 그대로 돌려줌 | 균형을 잃고 주저앉았는데도 마지막 자세만 완벽 |
| 미소의 경호원 | 건장한 성인 여성, 이어피스, 침착함 | 손짓 한 번에 경비팀이 플레이어를 들어 퇴장시킴 | 쓰러지면서도 한 손으로 통행 정리 |
| 산책 챔피언 | 등산 조끼의 중년 남성, 유쾌함 | 격려하듯 등을 두드리자 플레이어만 균형을 잃음 | 주저앉은 뒤 손을 뻗어 운동 종료 포즈 |
| 비밀 심판 | 평범한 차림의 성인 여성, 숨긴 호루라기, 엄격함 | 레드카드와 경찰 연행 | 넘어지며 들어 올린 점수 카드가 거꾸로 됨 |

근육질 남성의 역습과 여성 캐릭터의 경찰 연행은 반드시 완성할 대표 결말이다. 코드 전체를 `남성=난투, 여성=경찰`로 고정하지 않는다. 단서만 보고 정체를 확정하게 만드는 의상 연결도 피한다.

### 실제 실패 원인 분류

성공 여부를 먼저 계산한다. 성공이면 실패 연출 선택 함수를 호출하지 않는다. 실패일 때만 아래 순서로 최초 일치하는 `failureType` 하나를 선택한다.

| 우선순위 | failureType | 조건 | 장면의 출발점 |
|---|---|---|---|
| 1 | HIGH_POWER_MISS | 패드 비명중이고 P ≥ 0.85 | 강한 헛손질, 반동과 자멸 |
| 2 | MISS | 패드 비명중이고 P < 0.85 | 상대는 멀쩡하고 플레이어만 민망해짐 |
| 3 | NEAR_SUCCESS | 패드 명중이고 650 ≤ rawScore < 700 | 성공한 줄 알았던 짧은 안도 |
| 4 | UNDERPOWER_HIT | 패드 명중이고 maxRawScore < 700 | 힘이 부족해 상대가 거의 반응하지 않음 |
| 5 | OFF_CENTER_HIT | 위 조건에 해당하지 않는 실패 명중 | 힘은 충분했으나 명중 오차로 실패 |

0점이라는 이유만으로 무조건 빗나감으로 분류하지 않는다. 극저파워의 접촉과 실제 비명중은 별개다. 0.85와 650은 연출 구분용 설정값이며 점수식을 변경하지 않는다.

### 결말 조합과 제작 범위

연출은 **캐릭터 × failureType × 해당 상황에 맞는 연출 변형**으로 선택한다. 독립된 완성 영상들을 무작위로 섞지 말고, 접촉·방향·결과와 호환되는 조합만 선택한다.

| 연출 계열 | 사용 가능한 상황 | 코미디 구조 |
|---|---|---|
| DELAYED_NOTICE | UNDERPOWER_HIT, OFF_CENTER_HIT | 긴 정적 → 뒤늦은 시선 → 도망치기 전에 붙잡힘 |
| FALSE_RELIEF | NEAR_SUCCESS | 무릎이 꺾임 → 플레이어의 성급한 기쁨 → 다시 일어서는 상대 |
| SELF_OWN | HIGH_POWER_MISS | 강한 헛손질 → 소품 반동 → 상대는 무사하고 플레이어만 자멸 |
| AWKWARD_MISS | MISS | 아무 일도 없음 → 들키지 않은 척 → 자신의 소품 소리에 들킴 |
| FAKE_FORGIVENESS | UNDERPOWER_HIT, OFF_CENTER_HIT, MISS | 웃으며 용서하는 손짓 → 카메라가 추가 정보를 공개 → 이미 준비된 퇴장·연행 |

최초 제작 범위는 각 캐릭터의 대표 실패 장면 1개, 위 5개 연출 계열의 공통 동작 모듈, 캐릭터별 짧은 성공 반응이다. 모든 캐릭터×실패 유형을 전용 애니메이션으로 각각 만들 필요는 없지만, 모든 실패 유형에 유효한 장면이 있어야 한다.

각 캐릭터에 접촉 실패와 비명중 실패의 서로 다른 구성을 최소한 지원한다. 철근 씨와 민원 여왕에는 실제 실패 유형에 따른 차이가 특히 분명하게 드러나도록 한다. 대사만 교체하고 동작·타이밍·카메라가 모두 같은 장면은 별도 결말로 세지 않는다.

같은 캐릭터와 같은 실패 유형에서도 호환되는 변형이 여럿이면 아직 보지 않은 변형을 우선한다. 호환되지 않는 미발견 장면을 보여주기 위해 점수, 접촉 여부, 실패 유형을 바꾸지 않는다. 고파워 비명중 장면은 0% 입력 반복으로 수집할 수 없어야 한다.

### 데이터와 등장 관리

캐릭터 데이터에는 id, 이름 번역 키, 성인 연령, 외형·의상 원형, 성격, reactionType, successReactionId, 실패 유형별 가능한 endingIds, 대사 키를 포함한다. 결말 데이터에는 endingId, 연출 계열, 허용 실패 유형, 캐릭터 호환성, 필요한 에셋, 타임라인, 대표 장면 시점을 포함한다.

캐릭터는 셔플백에서 뽑고 판의 종료·재도전으로 셔플백을 초기화하지 않는다. 한 바퀴 내에서는 가능한 한 모두 만나게 하고, 새 백의 첫 상대가 직전 상대와 같으면 교환한다. 캐릭터는 준비 완료 후 라운드가 시작될 때 한 번만 소비한다.

캐릭터 선택, 배치, 게이지 초기 위상, 연출 선택, 시각 이펙트의 난수 스트림을 분리한다. 프레임 수·저사양 모드·스킵 여부가 다음 상대나 점수를 바꾸지 않게 한다. 연출 선택은 초기 발견 기록과 해당 라운드 입력을 포함하면 재현 가능해야 한다.

## 7. 카메라와 애니메이션 시나리오

### 공통 발사와 정체 공개

발사 직전 손목이 살짝 뒤로 당겨지고 양손 소품이 가속한다. 명중 순간 60~90ms 정도의 짧은 정지감과 파워에 맞는 보호패드 변형을 준다. 큰 화면 흔들림으로 결과를 가리지 않는다. 비명중에는 접촉음·패드 변형·명중용 정지감을 사용하지 않는다.

접촉 또는 헛손질 후 카메라가 뒤로 이동해 상대의 전신을 공개한다. 고개, 어깨, 몸통 순의 돌아보기와 읽히는 표정 뒤 이름·성격을 보여준다. 이미 계산한 판정 점수는 표시하되 실패 장면이 끝나기 전에 큰 GAME OVER 화면으로 얼굴과 연출을 덮지 않는다.

성공과 실패 모두 정체를 공개한다. 성공했다고 얼굴을 보기 전에 화면 밖으로 날려 보내지 않는다. 자멸형 실패에서도 카메라 한쪽에 상대의 앞모습을 남겨 ‘아무것도 하지 않은 상대’와 플레이어의 참상을 대비한다.

공통 도입부는 유지해도 되지만 모든 결말을 ‘험악한 상대에게 맞는다’로 끝내지 않는다. **긴 정적, 성급한 안도, 무반응, 자멸, 가짜 용서, 뒤늦게 공개되는 추가 정보**를 구분해 사용한다.

### 성공: 짧은 손맛과 캐릭터 고유 반응

대성공은 ‘접촉 → 잠깐 정지 → 눈이 커짐 → 전신 공개 → 한 박자 늦게 무너짐’으로 구성한다. 일반 성공은 이를 짧게 압축한다. 6장의 캐릭터별 고유 동작 하나를 얹고 점수 팝업이 얼굴을 가리지 않게 한다.

정체 공개 이후 성공 반응은 약 1~2초를 출발점으로 하고 곧바로 다음 상대에게 연결한다. 성공에는 손맛과 기록의 보상을 주되, 실패 연출 제작 비중을 줄여 긴 성공 영상을 늘리지 않는다. 모든 성공은 균형 상실로 끝나며 추가 반격·경찰 호출로 판정을 번복하지 않는다.

### 실패 A: 철근 씨 — 늦게 들킨 저파워 명중

적용: 철근 씨의 UNDERPOWER_HIT. 힘없는 접촉 뒤 상대가 거의 움직이지 않는다. 음악이 끊기고 어깨가 한 번 들썩인다. 카메라가 후퇴하면서 예상보다 거대한 상체가 드러난다.

플레이어가 장갑을 등 뒤로 숨기려는 순간 상대가 천천히 돌아본다. 손가락을 까딱하자 카메라가 두 사람의 전신이 보이는 3/4 구도로 바뀐다. 상대는 플레이어의 옷깃을 잡아 들어 올린다. 목을 조르지 않는다.

먼지 구름, 장갑 잔상, 두어 번의 과장된 흔들림으로 만화식 난투를 표현한다. 구름이 걷히면 플레이어는 납작해진 장난감 같은 자세로 앉아 있고 머리 위에 별이 돈다. 실제 구타 세부 동작과 부상은 보여주지 않는다.

결과 문구: “상대의 턴이었습니다.”

### 실패 B: 민원 여왕 — 이미 대기 중인 경찰

적용: 민원 여왕의 UNDERPOWER_HIT 또는 OFF_CENTER_HIT. 상대가 돌아보고 휴대전화를 한 번 누른다. 플레이어는 어색하게 웃으며 장갑을 숨긴다.

짧은 사이렌과 함께 경찰 역할 캐릭터 두 명이 양옆으로 미끄러져 들어온다. 연락을 받고 멀리서 오는 현실적 대기 대신 ‘이미 기다리고 있었다’는 타이밍을 사용한다.

플레이어가 양손을 모은 자세를 풀지 못한 상태에서 소품 수갑이 손목에 맞춰 채워진다. 수갑은 손목 소켓에 부착하고 팔을 뚫거나 공중에 뜨지 않게 한다. 경찰이 양옆에서 플레이어를 이끌고 퇴장한다.

결과 문구: “이번엔 다른 이유로 손을 모았습니다.”

### 실패 C: 699점 — 너무 빨랐던 세리머니

적용: NEAR_SUCCESS. 점수는 실제 값 그대로 표시하고 정확히 699점인 경우에만 제목에 699를 쓴다. 장면을 위해 점수를 699점으로 조작하지 않는다.

정체가 공개된 상대의 무릎이 꺾인다. 플레이어가 혼자 성공을 확신해 양손을 들고, 짧은 축하 소리가 어설프게 시작된다. 상대가 다시 몸을 세우자 소리가 끊긴다. UI는 계속 실제 실패 점수를 유지하고 성공 배지를 표시하지 않는다.

철근 씨는 플레이어가 든 손을 잡고 역습 장면으로, 민원 여왕은 축하 자세 그대로 수갑이 채워지는 장면으로 이어진다. 다른 캐릭터는 자신의 퇴장·반격 동작을 연결한다. 연결된 전체 본편이 약 3~5초 안에 끝나도록 기존 동작을 압축한다.

결과 문구: “세리머니가 조금 빨랐습니다.”

### 실패 D: 고파워 비명중 — 아무도 때리지 않았다

적용: HIGH_POWER_MISS. 양손 소품이 목표 옆을 힘차게 지나간다. 상대에게 접촉이나 피격 반응을 만들지 않는다.

카메라가 후퇴하는 동안 장갑 소품의 과장된 반동으로 플레이어가 한 바퀴 돌아 안전 매트 쪽으로 굴러간다. 상대는 뒤늦게 돌아보고 멀쩡히 서 있다. 플레이어는 매트 위에서 손을 번쩍 들었다가 조용히 내린다.

철근 씨는 운동 가방을 들어 길을 비켜주고, 민원 여왕은 휴대전화를 내려다보는 식으로 짧은 반응만 더한다. 같은 기본 리그와 동작을 공유해도 자기파괴와 상대의 무반응이라는 농담은 유지한다.

결과 문구: “상대는 아무것도 안 했습니다.”

### 실패 E: 보통 비명중 — 완벽하게 모른 척하다가

적용: MISS. 소품이 옆으로 지나가고 상대는 잠시 알아차리지 못한다. 플레이어는 조용히 장갑을 감추며 무관한 사람인 척한다.

장갑에서 작은 삑 소리가 난다. 상대가 돌아보며 정체가 드러나고, 플레이어만 어색한 엄지 척 자세로 멈춘다. 캐릭터별 짧은 퇴장·제압 동작으로 끝낸다. 비명중인데 상대가 아파하거나 패드를 문지르지 않는다.

결과 문구: “손은 숨겼는데, 소리가 남았습니다.”

### 실패 F: 가짜 용서 — 웃고 있어서 더 늦게 알았다

적용: FAKE_FORGIVENESS가 허용된 실패 유형과 캐릭터. 민원 여왕이나 비밀 심판은 웃으며 괜찮다는 손짓을 한다. 플레이어는 가슴을 쓸어내린다.

카메라가 조금 더 빠지면 뒤에서 이미 수갑을 준비하는 경찰이 보인다. 미소의 경호원은 같은 구성을 경비팀의 등장과 안전한 퇴장 동작으로 바꾼다. 플레이어가 계속 웃다가 옆을 보고 굳는 순간에 마지막 효과음을 준다.

결과 문구: “용서가 아니라, 인계였습니다.”

### 반복, 스킵, 결말 기록

실패의 대표 장면은 원인과 결말을 읽을 수 있는 약 3~5초의 본편으로 구성한다. 새 결말에는 ‘NEW’ 배지를 결과 화면에서만 표시하고, 조준 중 미래의 결말을 예고하지 않는다.

한 번 본 동일 endingId는 시작부터 명확한 건너뛰기 버튼을 제공한다. 새 결말은 기본적으로 재생하되 접근성을 위해 별도 ‘연출 최소화’ 설정을 제공할 수 있다. 새로운 결말의 마지막 핵심 장면을 보거나 정상 완료했을 때 seenEndingIds에 기록한다. 최소화로 보지 않은 새 장면은 발견·해금하되 ‘감상 완료’와 구분한다.

점수 확정, 결말 해금, 본 장면 기록, 게임오버 처리는 각각 한 번만 실행한다. 스킵으로 점수가 중복 저장되거나 다음 상대가 두 번 뽑히면 안 된다. 도감에서 결말을 재생하는 동안에는 새 점수·새 상대·새 게임오버를 발생시키지 않는다.

## 8. 아트 디렉션과 에셋 품질

시각 스타일은 **수집용 디자이너 토이의 입체감 + 만화책의 그래픽 효과 + 아케이드의 선명한 조작 UI**다. 저품질 구체와 막대만 조립한 데모, 이모지 캐릭터, 무표정 마네킹은 최종 결과물로 인정하지 않는다.

인체는 성인 비율을 유지하되 머리와 손의 표현을 약간 과장하라. 아동처럼 보이는 극단적인 유아형 비율은 사용하지 않는다. 실루엣은 둥글게, 의상 경계와 소품은 명확하게, 재질은 서로 다르게 표현한다.

배색의 출발점은 짙은 남청색 배경, 따뜻한 크림색 UI, 코랄색 액션 버튼, 청록색 성공 강조다. 무분별한 네온 발광과 전면 블룸은 사용하지 않는다.

| 에셋 | 필수 디테일 |
|---|---|
| 양손 소품 | 두 손이 결합한 실루엣, 엄지와 접힌 손가락 구분, 둥근 끝, 손등·손목 연결, 소매 경계 |
| 바지·보호패드 | 허리밴드, 봉제선, 포켓, 측면 주름, 서로 다른 천 재질, 외부 패드의 테두리와 눌림 |
| 캐릭터 얼굴 | 평상시·놀람·분노·무표정·당황·능청의 읽히는 표정, 눈썹과 시선의 독립 움직임 |
| 몸과 의상 | 목·어깨·골반의 자연스러운 연결, 캐릭터별 상체 실루엣, 옷깃·소매·신발 구분 |
| 경찰·수갑 | 경찰 역할을 식별할 수 있는 소품, 손목 위치에 맞는 수갑, 단순하지만 연결된 체인 |
| 배경 | 촬영장 바닥, 벽과 간판, 안전 매트, 깊이를 주는 소수의 소품, 캐릭터를 방해하지 않는 정보량 |
| SVG 효과 | 충격선, 말풍선, 점수 배지, 속도선, 별, 부채꼴 각도계, 실제 텍스트 기반 효과음 |

Three.js는 캐릭터, 양손 소품, 조명, 그림자, 카메라, 공간 속 동작을 담당한다. SVG는 게이지, 계기판, UI 아이콘, 말풍선, 충격 그래픽을 담당한다. 메인 3D 장면을 SVGRenderer로 전부 그리려고 하지 않는다.

캐릭터 제작은 로컬 GLB와 리깅 애니메이션, 또는 충분히 다듬어진 절차적 메시와 관절 계층을 사용하라. 모델 생성 도구가 없다면 bevel, 곡선 기반 형상, 재질 분리, 표정 파츠를 갖춘 절차적 모델을 직접 제작한다. 큰 구 두 개를 바지와 캐릭터의 완성형으로 제출하지 않는다.

메시와 텍스처는 화면에서 실제로 보이는 크기를 기준으로 품질을 배분하라. 조준 화면에서 가장 크게 보이는 장갑·바지·패드에 우선 투자하고, 정체 공개에서는 얼굴과 상체를 우선한다.

외부 에셋은 실제로 확보했고 사용 조건을 확인한 것만 사용한다. 존재하지 않는 GLB·이미지·음원 URL을 코드에 넣지 않는다. 프로젝트 안에 에셋을 포함하고 출처·라이선스·수정 내역을 ASSET_LICENSES.md에 기록한다. 직접 만든 에셋은 생성 소스도 남겨라.

## 9. 모바일 중심 화면 구성

게임 자체가 첫 화면이다. 랜딩페이지형 설명 섹션, 기능 카드, 긴 스크롤을 만들지 않는다.

상단에는 현재 라운드, 이번 판 누적 점수, 최고 기록을 배치한다. 우측에는 KO/EN, 사운드, 설정을 둔다. 중앙은 캐릭터와 액션이 차지한다. 하단에는 성공 기준 700점, 각도계, 파워 게이지, 엄지로 누르기 쉬운 큰 액션 버튼을 배치한다.

파워 게이지에는 정중앙 기준 성공 가능 경계를 표시하고, 파워 확정 뒤 최대 점수와 파워 부족 여부를 한 줄로 안내한다. 명중 위치에 따라 실제 점수가 낮아질 수 있음을 표현한다. 72.3% 이상을 ‘명중하면 무조건 성공’으로 표시하지 않는다.

현재 조작할 계기판만 강조하고 다음 계기판은 낮은 대비로 표시한다. UI 때문에 상대의 보호패드, 좌우 배치 차이, 양손의 출발 위치가 가려지지 않게 한다.

세로 화면을 기본으로 360px 너비부터 대응한다. 가로 화면도 실제로 재배치해 지원하고 화면 회전을 강제하지 않는다. 주소창 높이 변화, 노치, 하단 홈 인디케이터를 고려해 동적 뷰포트와 safe-area를 반영한다.

주요 액션 버튼 높이는 약 64px, 보조 버튼의 터치 영역은 최소 44×44 CSS px를 목표로 한다. 게임 입력 영역에만 필요한 touch-action을 적용하고 설정 화면이나 전체 페이지의 접근성 확대를 일괄 차단하지 않는다.

결과 화면에는 마지막 상대의 얼굴, 판정 점수, 실제 실패 원인, 이번 누적 점수, 최고 기록, 새로 발견한 결말 여부, 큰 재도전 버튼을 보여준다. 보조 기능인 결말 도감은 재도전 버튼의 시각적 우선순위를 빼앗지 않는다.

게임오버는 실패의 핵심 장면을 가린 채 먼저 덮지 않는다. 화면 어디를 눌러도 의도치 않게 재시작되는 구조를 피하고, 연출 스킵과 재도전을 같은 입력으로 연쇄 실행하지 않는다.

## 10. 한국어·영어 전환

모든 UI, 튜토리얼, 캐릭터 이름, 성격, 대사, 실패 유형, 결말 이름, 파워 안내, 결과 문구, 오류 안내를 번역 키로 관리하라. JSX·TS·SVG 안에 한국어 문장을 여기저기 하드코딩하지 않는다.

언어 우선순위는 저장된 선택, 브라우저 언어, 영어 기본값 순서다. 브라우저 언어가 한국어이면 한국어로 시작한다. KO/EN 전환은 즉시 반영하고 새로고침 없이 현재 라운드와 점수를 유지한다. 언어 변경으로 게이지가 초기화되거나 상대가 재추첨되어서는 안 된다.

영문 문구는 한국어를 기계적으로 직역하지 말고 짧은 게임 카피로 다듬어라. 효과음 글자도 이미지에 박아 넣지 말고 현지화 가능한 텍스트로 처리한다. 영어 길이에 맞춰 레이아웃을 검증한다.

| 위치 | 한국어 | 영어 |
|---|---|---|
| 타이틀 | 똥침각 | POKE & PANIC |
| 시작 문구 | 각은 봤고, 앞은 못 봤다. | Perfect angle. Terrible idea. |
| 파워 버튼 | 파워 결정 | LOCK POWER |
| 각도 버튼 | 각도 결정 · 발사 | LOCK & LAUNCH |
| 대성공 | 정확도는 프로. 판단력은 글쎄. | Pro aim. Questionable judgment. |
| 빗나감 | 힘은 충분했다. 방향만 빼고. | All power. No direction. |
| 반격 | 상대의 턴입니다. | THEIR TURN. |
| 경찰 | 이번엔 다른 이유로 손을 모았습니다. | Hands together. Different reason. |
| 재도전 | 반성은 다음 판에. | Regret can wait. |
| 파워 경계 | 정중앙 기준 성공 가능 | Can succeed with a center hit |
| 파워 상한 | 정중앙 명중 시 최대 {score}점 | Center-hit maximum: {score} |
| 파워 부족 | 파워 부족 · 그래도 방향은 정하세요 | Too little power. Still pick your angle. |
| 근접 실패 | 세리머니가 조금 빨랐습니다. | Celebrated a little too soon. |
| 고파워 비명중 | 상대는 아무것도 안 했습니다. | They did absolutely nothing. |
| 보통 비명중 | 손은 숨겼는데, 소리가 남았습니다. | Hid the hands. Not the squeak. |
| 가짜 용서 | 용서가 아니라, 인계였습니다. | Not forgiven. Handed over. |
| 새 결말 | 새로운 결말 발견 | NEW ENDING DISCOVERED |
| 결말 도감 | 어떻게 망했나 | THE HALL OF FAILS |

## 11. 사운드·접근성

짧은 게이지 틱, 파워 고정음, 스프링 발사음, 패드의 고무성 접촉음, 성공 팡파르, 실패 직전의 정적, 낮은 음량의 코미디 사이렌을 구분하라. 현실적인 비명이나 신체 타격음은 사용하지 않는다.

오디오는 첫 사용자 입력 이후 초기화하거나 resume하고, 재생 거절을 처리하라. 소리가 없어도 모든 판정 정보를 이해할 수 있게 한다. 음소거 선택은 저장하고 다음 접속에서도 유지한다. 진동은 지원되는 환경에서만 선택적으로 사용하고 필수 피드백으로 취급하지 않는다.

prefers-reduced-motion과 별도의 화면 흔들림 설정을 반영한다. 움직임 감소 모드에서는 카메라 흔들림·급격한 줌·과도한 파티클을 줄이고, 게임 규칙에 필요한 게이지 운동은 유지한다. 빠르게 반복되는 섬광은 사용하지 않는다.

키보드 조작, 명확한 포커스 표시, 버튼 접근성 이름을 제공한다. 스크린리더 알림은 단계 변경과 결과에 한정하고 매 프레임 게이지 수치를 읽지 않는다.

## 12. 기술 스택과 상태 관리

기본 스택은 **Vite + TypeScript + Three.js + HTML/CSS/SVG UI**로 선택한다. 새로운 프로젝트라면 불필요한 UI 프레임워크를 추가하지 않는다. 기존 React 프로젝트에서는 메뉴·설정·결과 UI만 React로 관리하고 프레임 루프를 React 재렌더링에 연결하지 않는다.

렌더러는 WebGLRenderer를 기본으로 사용하고 WebGL 2 지원 여부와 렌더러 생성 실패를 처리한다. WebGPU를 실행 필수 조건으로 만들지 않는다. 미지원 환경에서는 SVG 안내 화면과 재시도를 제공한다. 구현하지 않은 ‘2D 모드’ 버튼을 보여주지 않는다.

대규모 물리 엔진은 기본 의존성에서 제외한다. 접촉 판정은 단순화된 충돌 프록시로, 넘어짐과 난투는 제어 가능한 키프레임 애니메이션으로 구현한다.

### 상태와 데이터의 책임

```text
BOOT → LOADING → MENU → PREPARE_ROUND → INTRO → POWER → AIM
     → FIRE → IMPACT_OR_MISS → REVEAL

REVEAL 성공 → SUCCESS_SCENE → NEXT_ROUND → PREPARE_ROUND
REVEAL 실패 → FAILURE_SCENE → GAME_OVER
GAME_OVER → RETRY → PREPARE_ROUND
```

`PREPARE_ROUND`에서 캐릭터·배치·에셋을 준비한다. 준비 완료 후에만 백에서 상대를 소비하고 라운드 식별자를 확정한다. `FIRE` 진입 시 불변 ShotResult에 파워, 각도, 좌표, 접촉 여부, accuracy, rawScore, maxRawScore, 성공 여부, failureType, 해당 endingId를 저장한다.

점수 계산 → 실패 원인 분류 → 호환되는 결말 선택을 분리한다. 결말 선택 함수는 점수·상대·패드·발사 방향을 수정할 권한을 갖지 않는다. 연출 선택 시점의 발견 기록도 재현용 입력에 포함한다.

런의 점수·라운드 번호·콤보와 누적 프로필의 최고 기록·발견·셔플백을 분리한다. RETRY는 런만 초기화한다. 다시 시작할 때 전체 저장소나 캐릭터 백을 초기화하지 않는다.

일시정지는 현재 상태와 경과 시간을 보존하는 상위 제어로 구현한다. 탭 비활성화, 창 포커스 상실, 화면 잠금 등에서 자동 일시정지하고 복귀 시 재개 버튼을 제공한다. 돌아오는 순간 게이지나 애니메이션이 몇 초씩 건너뛰지 않게 한다.

스킵은 해당 타임라인을 정리하고 정상 종료와 동일한 멱등 종료 함수로 이동한다. 새 결말의 발견·감상 기록은 7장의 규칙을 적용한다. 타이머와 콜백에는 라운드 식별자를 적용해 이전 라운드 이벤트를 무효화한다.

### 프로젝트 구조

```text
src/
  game/       # 상태 머신, 공통 시계, 입력, 점수, 실패 분류, 설정
  scene/      # 렌더러, 카메라, 조명, 좌우 배치, 배경, 양손 소품
  characters/ # 캐릭터 데이터, 생성, 리그, 표정, 셔플백
  endings/    # 결말 데이터, 호환 조건, 선택, 발견·감상 상태
  animation/  # 발사, 정체 공개, 성공, 반격, 경찰, 자멸, 공통 동작
  ui/         # HUD, SVG 게이지, 결과, 결말 도감
  i18n/       # ko/en 메시지, 번역 함수
  audio/      # 오디오 초기화, 효과음, 음량
  storage/    # 런과 프로필 분리, 스키마 버전, 오류 복구
public/assets/
tests/
README.md
ASSET_LICENSES.md
```

실제 책임에 맞게 조정하되 모든 코드를 한 파일에 넣지 않는다. 도감 재생은 게임 실행과 분리된 프리뷰 상태에서 같은 연출 모듈을 재사용한다.

## 13. 모바일 성능과 안정성

최초 목표는 주요 모바일 기기에서 60fps다. 이를 모든 기기에 대한 보장으로 표현하지 않는다. 저성능 환경에서는 이펙트와 렌더링 해상도를 줄여 30fps 수준에서도 조작이 유지되도록 하라.

모바일 DPR 상한 1.5, 데스크톱 상한 2를 초기값으로 두고 성능에 따라 조정한다. 조준 중 드로콜 100 이하, 화면 내 삼각형 약 10만 이하, 최초 플레이에 필요한 압축 전송량 약 5MB 이하를 초기 예산으로 삼아 실측하라. 기준을 넘으면 사유와 개선 방법을 기록한다.

고비용 실시간 그림자와 후처리보다 제한된 조명과 접지 그림자를 우선하라. 반복 소품은 지오메트리·재질을 공유하고, 파티클은 재사용한다. SVG의 큰 블러 필터를 화면 전체에서 계속 갱신하지 않는다.

파워 조작 시작 전에 해당 상대의 앞모습, 성공 반응, 모든 유효 실패 유형에 필요한 공통·전용 에셋을 준비한다. 결말이 정해지는 발사 이후에 새 모델 다운로드를 시작하지 않는다. 상대·경찰·경비원·소품의 공통 리그와 동작은 공유하고 캐릭터별 차이는 얼굴·소품·타이밍으로 구성한다. 메뉴·도감용 리소스와 후속 상대는 지연 로딩하거나 여유 시간에 미리 준비하되, 다음 라운드는 필요한 에셋이 준비된 뒤 시작한다.

재도전의 기본 경로는 이미 확보한 공통 에셋을 재사용해 즉시 진입하도록 구성한다. 불가피하게 로딩이 필요하면 실제 진행과 오류·재시도를 표시하고, 로딩 지연을 고정 카운트다운이나 긴 전환 영상으로 숨기지 않는다.

재도전할 때 렌더러를 계속 새로 만들지 않는다. 이벤트 리스너, 지오메트리, 텍스처, 오디오 노드를 수명에 맞게 정리하라. WebGL context loss, 에셋 로딩 실패, 저장소 접근 실패를 처리하고 무한 로딩 화면에 머무르지 않는다.

## 14. 재플레이, 결말 수집, 난이도

### 재플레이의 두 가지 보상

성공은 타이밍 숙련, 최고 점수, 연속 성공 수를 보상한다. 실패는 정체와 반전의 발견을 보상한다. 어느 쪽도 다른 쪽을 무효화하지 않는다. 일부러 실패해 장면을 찾아보는 플레이는 허용하되, 모든 결말을 동일한 저파워 입력만으로 얻지는 못하게 한다.

실패 뒤 점수 런은 종료한다. 수집은 별도로 유지한다. 강제 광고, 기다려야 충전되는 재도전 횟수, 유료 부활, 라이프·도주 미니게임을 넣지 않는다.

### 재도전 시 초기화 범위

| 항목 | RETRY 처리 |
|---|---|
| 이번 판 점수, 라운드 번호, 콤보 | 초기화 |
| 최고 점수, 최고 연속 성공 | 유지 |
| 발견한 캐릭터, 해금한 결말, 실제 본 결말 | 유지 |
| 현재 캐릭터 셔플백, 소비 위치, 직전 상대 | 유지 |
| 언어, 사운드, 연출·접근성 설정 | 유지 |
| 기존 라운드의 타이머, 애니메이션, 임시 이펙트 | 정리 후 새 라운드 생성 |

백 상태는 저장소 사용 가능 시 새로고침 뒤에도 복원한다. 저장 거부·손상 시에는 메모리 상태로 계속하고, 게임을 진행하는 동안에는 판이 끝나도 그 메모리 백을 유지한다.

### 결말 도감과 발견 규칙

발견한 캐릭터의 앞모습과 짧은 소개, 실제로 해금한 결말의 썸네일·짧은 제목을 보여준다. 미발견 인물은 실루엣, 미해금 장면은 제목을 숨긴 슬롯으로 표현한다. 조준 화면이나 잠긴 슬롯에서 정체·농담의 마지막 장면을 먼저 노출하지 않는다.

플레이로 해당 endingId에 도달하면 해금한다. 본편의 핵심 마지막 장면까지 보거나 정상 완료하면 감상 완료로 표시한다. 해금된 결말은 도감에서 재생할 수 있고, 점수·백·콤보를 변경하지 않는다. 캐릭터를 처음 공개한 것만으로 그 캐릭터의 모든 결말을 해금하지 않는다.

결말은 실질적인 동작·구성·마지막 반전이 다를 때 별도 endingId를 부여한다. 이름·대사·의상 색만 바꿔 수집 개수를 부풀리지 않는다. 동일 결말의 캐릭터별 반응 차이는 필요한 경우 하위 변형으로 기록한다.

미발견 우선 정책은 같은 캐릭터·실패 유형 안에서 호환되는 결말 후보에만 적용한다. 도감 완성을 돕기 위해 성공을 실패로 바꾸거나 실패 유형을 임의 재분류하지 않는다.

### 난이도와 흐름

초반에는 느린 게이지로 조작을 익히게 하고 이후 점진적으로 속도를 올리되 4장의 상한을 둔다. 게이지 속도와 좌우 배치는 라운드 사이에만 변경한다. 공개된 성공 기준 700점과 캐릭터 공통 패드 규칙은 유지한다.

난이도 때문에 성공률이 낮아질 수는 있으나 실패 영상을 보여주려고 숨겨진 난수로 강제 실패시키지 않는다. 높은 숙련도로 계속 성공하는 플레이도 정당하게 인정한다. 짧은 성공 반응과 기록 상승이 해당 플레이를 보상한다.

### 검증할 질문

작은 범위의 플레이 테스트로 **실패 후 재도전하는지, 실패 원인을 이해하는지, 같은 결말을 다시 볼 때 지루해하는지, 다른 실패 유형을 스스로 시도하는지**를 확인한다. 의도적 실패를 일괄 문제로 보지 말고 결말 탐색인지 조작 포기인지 구분한다.

실패 장면 종료 후 재도전 비율, 처음 보는 결말과 반복 결말의 스킵 차이, 파워 부족 이해 여부, 반복 저파워 입력의 이유를 관찰한다. 표본·환경을 기록하고 플레이 테스트 없이 ‘재미 검증 완료’나 임의의 재미 점수를 보고하지 않는다. 초기 버전은 로컬 테스트 로그로 충분하며 외부 분석 SDK와 서버를 필수로 추가하지 않는다.

최고 기록과 발견 정보는 버전·기본값을 갖춘 로컬 저장으로 관리한다. 서버 없는 기록을 글로벌 랭킹처럼 표시하지 않는다. 공유는 지원되는 텍스트 공유·복사 정도로 두고 핵심 조작과 실패 연출을 먼저 완성한다.

## 15. Vercel 배포 준비

첫 버전은 정적 프런트엔드로 완성하라. 회원가입, 데이터베이스, 결제, LLM API, 서버리스 함수, 외부 비밀키를 필수 구성에 넣지 않는다.

Vite 배포 설정의 기본값은 다음과 같다.

```text
Framework Preset: Vite
Install Command: npm ci
Build Command: npm run build
Output Directory: dist
```

npm run dev, build, preview, typecheck, test를 실제 동작하는 스크립트로 제공하라. preview는 로컬 빌드 검증에만 사용하고 배포 서버로 취급하지 않는다. Node.js와 패키지는 구현 시점에 호환되는 지원 버전을 확인하고 lockfile로 재현성을 확보하라.

게임 화면 전환은 기본적으로 단일 경로 안에서 처리한다. 실제 URL 하위 경로를 도입한 경우에만 Vercel의 SPA rewrite 설정을 추가하고 직접 접속·새로고침을 검증하라. 에셋 요청이 HTML로 잘못 응답하는지도 확인한다.

에셋 경로에 localhost, 개발자 개인 경로, 임시 다운로드 주소를 남기지 않는다. README에는 설치, 실행, 테스트, 빌드, Vercel 설정, 에셋 출처, 알려진 제한사항만 명확히 작성하라.

실제 배포 권한이나 실행 결과가 없으면 배포 완료라고 말하지 않는다. 배포 가능한 빌드와 실제 공개 URL 확인을 구분하라.

## 16. 구현 순서와 완료 기준

### 구현 순서

먼저 철근 씨와 민원 여왕으로 파워·각도·발사·점수·정체 공개·성공·게임오버·재도전의 전체 루프를 연결한다. 같은 상대에게 저파워 명중, 비명중, 근접 실패가 실제로 다른 장면을 만드는지 확인한다. 캐릭터 수만 늘리기 전에 이 연결을 완성한다.

다음으로 공통 실패 연출 계열과 등장 백의 판 간 유지, 결말 해금·감상 기록을 연결한다. 이후 8개 캐릭터의 외형·대표 결말·짧은 성공 반응을 완성하고 장갑·바지·표정·카메라·사운드를 다듬는다. 모바일·한영 전환·접근성은 각 단계에서 검증하고 최종 성능·배포 검증을 마무리한다.

도감·공유 때문에 핵심 연출을 정적인 카드로 대체하지 않는다. 모든 캐릭터×모든 실패 유형의 전용 애니메이션을 만드는 대신, 공통 모듈의 조합으로 실제로 다른 장면을 완성한다.

### 기능·일관성 검증

| 검증 영역 | 완료 기준 |
|---|---|
| 기본 조작 | 탭 두 번으로 파워·각도 고정과 발사 완료. 중복 발사·3초 강제 대기 없음 |
| 성공 가능 안내 | 파워 60%의 최대 점수 570점과 성공 불가 표시. 성공 가능 경계는 공통 점수 함수와 일치 |
| 경계 반올림 | 표시용 72.3%를 조건으로 하드코딩하지 않음. rawScore 반올림 경계 전후 테스트 |
| 저파워 각도 | 파워 부족 상태에서도 각도 조작 유지. 같은 파워의 명중과 비명중이 다른 실패 유형·장면으로 연결 |
| 판정 | 최고 파워 비명중은 0점, rawScore 699는 실패, 700은 성공, 콤보로 판정 역전 없음 |
| 실패 분류 | HIGH_POWER_MISS, MISS, NEAR_SUCCESS, UNDERPOWER_HIT, OFF_CENTER_HIT의 순서·조건·fallback 검증 |
| 공정성 | 상대 정체·성별·도감·연출 선택이 점수와 성공 여부를 바꾸지 않음. 캐릭터별 비밀 성공 조건 없음 |
| 조준 변주 | 좌우 배치에 따라 실제 정답 방향 변경. 가이드·계기판·충돌·이동 궤적 일치 |
| 시각적 명중 | 패드 접촉 위치와 점수 일치. 비명중에 피격음·패드 변형·아픈 반응 없음 |
| 정체 공개 | 같은 전신 캐릭터 유지. 공개 전 얼굴·소품·그림자로 정체가 먼저 드러나지 않음 |
| 대표 결말 | 근육질 남성 역습과 경찰 수갑 연행을 실제 3D 동작으로 구현 |
| 코미디 변주 | 늦은 들킴·성급한 안도·고파워 자멸·민망한 비명중·가짜 용서를 구분. 대사만 다른 장면으로 대체하지 않음 |
| 성공 연출 | 캐릭터별 짧은 고유 반응과 확실한 균형 상실. 성공 후 강제 반격·체포 없음 |
| 등장 백 | 8개 캐릭터 기준 백 소진 전 중복 등장 없음. 게임오버·재도전으로 백 초기화 없음. 백 경계 연속 중복 방지 |
| 결말 선택 | 실제 실패 원인에 호환되는 후보만 사용. 저파워 반복으로 고파워 비명중 전용 결말 해금 불가 |
| 재도전 | 한 번의 입력으로 새 상대 진입. 라이프·부활·도주 후 계속 없음. 런만 초기화하고 발견 기록 유지 |
| 도감·스킵 | 새로운 결말 해금과 실제 감상 구분. 본 장면은 스킵 가능. 도감 재생이 점수·백을 변경하지 않음 |
| 상태·재현 | 동일 초기 프로필·시드·배치·입력이면 동일 결과. 일시정지·언어 전환·스킵으로 중복 저장이나 다음 상대 이중 소비 없음 |
| 한영·모바일 | 진행 중 언어 전환 유지, 두 언어 레이아웃 정상. 세로·가로·주소창 변화·노치·홈 영역 대응 |
| 안정성·성능 | 오디오 거절·저장소 오류·에셋 실패·WebGL 미지원 대응. 저사양 모드에서도 판정 동일 |
| 빌드 | 타입 검사·테스트·프로덕션 빌드 결과 확인, 에셋 404와 치명적 콘솔 오류 점검 |

### 개발 도구와 실제 검증 범위

개발 모드에 캐릭터·배치 선택, 파워·각도 입력, 점수·failureType 표시, 각 endingId 미리보기, 초기 프로필·시드 고정, fps를 확인하는 디버그 패널을 둔다. 강제 연출 미리보기는 실제 점수 검증과 구분하고 프로덕션 빌드에서는 노출하지 않는다.

Playwright 등으로 조작·언어·뷰포트·상태 전이를 테스트한다. 데스크톱 Chromium, Android Chrome·Samsung Internet, iOS Safari를 검증 대상으로 명시하되 실제 테스트한 환경과 실기기 검증이 필요한 환경을 구분한다. 화면 에뮬레이션이나 WebKit 자동화만으로 실제 iPhone 성능을 검증했다고 쓰지 않는다.

기능 테스트가 통과한 것과 재미가 확인된 것은 별개다. 14장의 질문으로 조작·코미디·재도전을 관찰하고, 실제 수행한 검증만 결과로 보고한다.

최종 산출물은 실행 가능한 전체 소스, 로컬 에셋과 생성 소스, 에셋 출처, 결말·캐릭터 데이터, 테스트, 빌드 설정, README다. 최종 보고에는 구현 범위, 실행 명령, 실제 테스트 결과, 남은 제한사항을 짧게 정리한다.

**최종 기준: 성공을 노리는 두 번의 조작이 손맛을 만들고, 실패한 방식이 그에 맞는 코미디 장면으로 이어지며, 플레이어가 ‘이번에는 어떻게 망할까’라는 기대를 가지고 한 번 더 도전하는 게임으로 완성하라.**
