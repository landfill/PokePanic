# 웹 우선 개발과 마켓 앱 전환

현재 제품 목표는 모바일 웹이다. M1~M4 및 8종 콘텐츠의 기존 수용 기준은 유지한다.
향후 Android/iOS 앱은 같은 웹 코어를 Capacitor 등으로 패키징하는 후보 경로다.
이번 하니스는 네이티브 의존성·프로젝트·PWA·결제·서버를 추가하지 않는다.

## 지금 유지할 경계

- game은 DOM, 저장 API, 네이티브 플러그인을 직접 호출하지 않는다.
- storage 구현 시 비동기 read/write 계약 뒤에 ProfileV1 검증·마이그레이션을 연결한다.
  웹 저장과 앱 저장 어댑터가 같은 프로필 계약을 사용하게 한다. 매 프레임 저장하지 않는다.
- 브라우저 visibility/blur와 향후 앱 lifecycle은 같은 pause 경로로 연결하고 명시적 재개를 유지한다.
- 에셋은 확보·출처 확인된 파일만 사용한다. 정적 웹 배포와 앱 번들에서 같은 자산을 로드할 수 있게 한다.
- 공유, 뒤로가기, safe-area 등 플랫폼 차이는 UI/어댑터에서 처리한다. 판정은 바꾸지 않는다.
- 웹 저장과 설치 앱 저장의 자동 이전을 가정하지 않는다. 이전 요구가 생기면 별도 범위로 결정한다.

## 전환 검증 시점

M1 두 캐릭터 루프 뒤, 콘텐츠 확장 전에 앱 패키징 실험을 수행하는 것을 권장한다.
실험 착수 시 ADR과 별도 작업 브랜치로 도구·지원 OS·기기 범위를 확정한다.
웹의 M1 종료 조건이나 이번 작업에 앱 제작 의무를 추가하지 않는다.

| 게이트 | 필요한 증거 |
|---|---|
| 웹 출시 | QA의 M4 게이트, 모바일 브라우저·실제 URL 검증 |
| 앱 기술 검증 | 실제 Android/iPhone에서 WebGL, 입력, 잠금·복귀, 오디오, 저장, 메모리·프레임 시간 |
| 앱 제품화 | 번들 에셋·오프라인 시작, 뒤로가기·화면 영역, 설치·업데이트 후 기록, 아이콘·서명 |
| 마켓 제출 | 최신 정책 확인, 실제 영상·스크린샷의 표현 검수, 연령 등급·개인정보·에셋 권리·제출 자료 |

WebView 패키징이 성능 개선이나 심사 승인을 보장하지 않는다.
성인 배우·폼 장갑·보호패드 설정은 실제 화면과 홍보 자료에도 일치해야 한다.
스토어 요구사항은 제출 시점에 공식 문서로 다시 확인한다.
