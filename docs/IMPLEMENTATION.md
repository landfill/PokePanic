# 구현 순서와 작업 백로그

기간·인력·재미 목표치는 아직 추정하지 않았다. 각 단계의 종료 조건을 만족한 뒤 다음 단계로 간다.
담당은 현재 미배정이다. 작업할 때 templates/TASK.md를 복사해 요구사항 ID와 증거를 남긴다.

| 단계 | 의존 | 작업 | 종료 조건 | 현재 |
|---|---|---|---|---|
| M0 준비 | 원본 | 문서, 계약, 판정 기준, 테스트, lockfile, CI | check·브라우저 smoke 및 실제 결과 기록 | 완료, STATUS 참조 |
| M1 두 인물 전체 루프 | M0 | 상태·입력·3D 장갑/패드·철근/민원·공개·성공/실패·재도전 | 두 번 입력부터 다음 상대/게임오버·재도전까지 플레이 가능 | 기능 연결, 품질 검수 진행 |
| M2 지속성과 변주 | M1 | 5계열 공통 모듈, 호환 선택, 백, 저장, 수집, 스킵, 재현·디버그 | 반복 런에도 공정성·다양성·기록 유지, 통합 회귀 통과 | 핵심 연결, 8인물 회귀 진행 |
| M3 8인물 콘텐츠 | M2 | 8종 전신·대표 결말·짧은 성공·얼굴·소품·사운드 | 각 인물의 원인별 반응과 아트 기준 검수 | 8리그·데이터 연결, 연출/시각 검수 진행 |
| M4 제품 검증 | M3 | 실제 모바일·장애·성능·플레이 테스트·배포 검증 | QA 출시 게이트와 증거 충족 | 예정 |

## 작업 착수 기준

환경 준비가 끝나고 실제 M1 구현을 요청받으면 [브랜치 전략](BRANCHING.md)에 따라 분기하고 AGENTS의 구현·검증 스킬을 적용한다.
웹/앱 공통 경계는 [PLATFORMS](PLATFORMS.md)를 따른다. 앱 패키징 실험은 M1 이후 별도 작업 후보이며,
현재 M1~M4 제품 수용 기준과 요구사항 상태를 변경하지 않는다.

## 다음 실행할 M1 작업

1. M1-01 (코어·어댑터 완료, 제품 화면 통합은 M1-02~06): game state/input 어댑터. POWER→AIM→FIRE, 해제 게이트, 키 반복·멀티터치·버튼 전파 방어. R-INPUT/R-CLOCK.
2. M1-02 (대표 두 인물 기본 장면 연결, 시각 품질 보강 중): 장면 뼈대. 같은 전신 리그 두 종, 월드 패드·장갑 끝점 경로, 원점·패드 스냅샷. R-GEOMETRY/R-REVEAL.
3. M1-03 (코어·별도 입력 통합·제품 기본 루프 연결): 점수·run 연결. 기준 함수 사용, 콤보 지급, 성공 다음 상대·실패 게임오버·단일 재도전. R-SCORE/R-LOOP/R-COMBO.
4. M1-04: 두 인물 연출. 저파워 접촉·비명중·근접 실패가 다른 동작, 철근 난투·민원 수갑·성공 붕괴. R-ENDINGS/R-SUCCESS.
5. M1-05: KO/EN·모바일·설정·오디오·중지·재개를 위 단계에 함께 연결. R-I18N/R-MOBILE/R-A11Y.
6. M1-06: Playwright 게임 통합 + 연속 영상 검수. 하니스 준비 화면은 제품 화면으로 교체하고 smoke를 실제 시작 화면에 맞춰 갱신.

M1 종료 전: 60 중앙 접촉, 60 비명중, 100 비명중, 699, 700을 개발 입력으로 각각 재현한다.
대표 캐릭터를 늘리기 전에 실패 원인을 보고 재도전까지 이해할 수 있는지 확인한다.

## M2의 우선 회귀

준비 실패가 백을 소비하지 않는지, 런 종료 10회 뒤에도 백 순서가 유지되는지 확인한다.
스킵과 정상 종료 동시 발생, 연출 최소화, 도감 재생, 저장 오류를 주입한다.
시드·초기 프로필·입력 시각을 기록한 완전 재현 fixture를 도입한다.
개발 패널은 실제 판정 재현과 강제 연출 미리보기를 분리하고 제품 빌드에서 제거한다.

## 위험과 결정이 필요한 시점

| 위험 | 해결할 단계 | 확인 방법 |
|---|---|---|
| 점수식에 비해 조준 폭이 지나치게 좁음 | M1 | 실제 거리·패드 반경·화면 배치와 성공 각도 폭 기록 |
| 작은 화면에서 정체 은폐와 패드 가시성 충돌 | M1 | 360px 세로/가로 연속 캡처 |
| 실패 변형이 대사 교체에 그침 | M1/M3 | 동일 입력 원인별 타임라인 영상 비교 |
| 매번 새 연출을 보는 피로 | M2/M4 | seen·스킵·연출 최소화 및 관찰 로그 |
| 절차 모델 제작비·모바일 예산 | M3 | 화면별 삼각형·드로콜·DPR·메모리 실측 |
| 저파워 반복이 포기인지 탐색인지 불명확 | M4 | 입력 기록과 플레이 후 짧은 인터뷰 |

필요 없는 서버·광고·추리 기능을 추가해 위험을 우회하지 않는다.
디자인 변경은 decisions의 후속 번호 문서에 이유·대안·수용 기준 영향을 기록한다.

## 디자인 작업 인계

화면·캐릭터 제작 전 [현재 디자인 결정](DESIGN_DECISIONS.md)과 [디자인 진행](DESIGN_WORKFLOW.md)을 확인한다.
M1 대표 두 인물은 시트·화면·짧은 플레이로 함께 검증하고, 방향과 관찰 결과를 반영한 뒤 M3 콘텐츠로 확장한다.
환경 준비나 의견 질문만으로 이 제작을 시작하지 않는다.
