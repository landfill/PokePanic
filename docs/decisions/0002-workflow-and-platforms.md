# ADR 0002 — 구현 전 작업 하니스와 플랫폼 경계

날짜: 2026-09-11. 상태: 채택.

사용자는 저장소 지침·스킬·하니스와 브랜치 전략 구성을 요청했다.
웹 우선 개발 후 마켓 앱 전환을 검토한 맥락을 반영한다.

1. M0 환경 준비는 main에서 진행한다. 실제 제품 구현 착수 시부터 짧은 codex/<type>/<slug> 브랜치를 사용하며 develop은 두지 않는다.
2. 저장소 전용 스킬은 .agents/skills에 버전 관리한다. 전역 스킬을 수정하지 않는다.
3. 작업 계약·PR 양식·검증 기록과 기존 check/E2E를 연결한다.
4. PR 브랜치 이름 검사를 CI에 추가한다. 원격 보호 정책은 별도 관리자 설정이다.
5. 웹 코어와 플랫폼 저장·lifecycle 경계를 유지한다. Capacitor 도입은 후속 기술 검증으로 남긴다.

규칙·게임 콘텐츠·성공 기준은 변경하지 않는다. 원본과 28개 제품 요구사항의 상태도 올리지 않는다.
대안인 develop 및 플랫폼별 장기 브랜치는 현재 규모에서 동기화 비용을 늘리므로 채택하지 않는다.
하니스 검사 통과는 M1 완료나 앱 심사 통과를 뜻하지 않는다.

## 사용자 정정 반영

2026-09-11: 준비 중 브랜치 생성은 사용자 의도와 달랐다. 같은 커밋을 가리키던 준비용 브랜치를
삭제하고 미커밋 변경을 보존해 main으로 복귀했다. 구현 브랜치 정책은 실제 구현 착수 시부터 적용한다.
