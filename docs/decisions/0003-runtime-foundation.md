# ADR 0003 — M1 실행 코어와 A 토이 스튜디오

2026-09-11. 사용자 지시: 승인 필요한 단계 외 필요한 구현을 계속 진행.

## 결정

- 시각 방향은 비교판 제시 후 사용자가 A 토이 스튜디오를 선택했다.
- M1 대표 철근 씨·민원 여왕을 절차 메시로 제작한다. 원본·외부 모델 다운로드 없이 실제 생성 소스를 보존한다.
- 입력·좌표 판정·런 상태는 GameSession으로 연결하고 DOM/UI/오디오/Three 렌더러와 분리한다.
- FIRE에서 power/angle/time/origin/pad를 복사·동결한다. 연출 후 모델 변형은 판정을 바꾸지 않는다.
- 성공 점수 지급은 finishScene 한 경로로 멱등 적용한다. 실패는 앞서 얻은 점수를 보존하고 추가 지급 없이 GAME_OVER로 이동한다.
- CharacterBag는 런 밖 세션 소유다. peek는 후보/RNG를 예약하고 준비 완료 commit만 소비한다.
- 난수 기준 v1은 uint32 LCG(1664525, 1013904223, modulus 2^32). 스트림별 인스턴스 분리.
  암호 용도가 아니며 tests/unit/character-bag.test.ts에 seed 0 고정 출력이 있다.
- runtime에서는 현재 실제 제작한 두 인물만 사용한다. 8인물 content-plan을 에셋 완료 목록으로 읽지 않는다.
- 저장은 주입한 I/O에 한정하고, 미래 버전은 덮어쓰지 않는다. 실패한 저장도 메모리 프로필을 유지한다.

## 변경하지 않은 규칙

두 번 입력, 상대당 한 발, 첫 실패 종료, 성공 rawScore>=700, 저파워 AIM 유지, 같은 전신 공개.
점수·실패 분류와 결말 후보 선택은 별도 함수다. 새 규칙을 추가하지 않았다.

## 아직 필요한 일

실제 원인별 타임라인과 대표 난투·소품 수갑·성공 붕괴는 현재 기본 회전/반응보다 더 구현해야 한다.
FailureTimeline/호환 선택 코어는 테스트됐지만 실제 연출·수집 UI까지 연결된 것은 아니다.
8종 확장, 완전 재현, 도감, 전체 장애 주입, 실기기와 재미 검증은 후속 작업이다.

## 대표 플레이 공간 조정

최초 카메라에서 폼 장갑 대부분이 하단 밖으로 나가 가시성을 충족하지 못했다.
발사 원점 z=1.3, y=1.5, 패드 중심 z≈0.39, 반경 .31/.24와 장갑 .55 스케일을 초기 제품 조정값으로 사용한다.
패드 크기·높이는 두 인물 공통이며 장갑 로컬 끝점(0,0,0)은 스케일 후에도 그대로 ray 원점이다.
근접 카메라 y1.72/z3.6, FOV22에서 시작해 공개 FOV28로 이동한다.
이는 실제 화면을 위한 조정이며 기준 판정 fixture의 거리·반경을 바꾸거나 기대값을 낮추지 않는다.
성공 각도 폭·재미는 실제 플레이로 추가 확인한다.
