# 스킬·지침 점검 — 2026-09-11

근거: 사용자 지정 [OpenAI Model guidance](https://developers.openai.com/api/docs/guides/latest-model)의
Prompting best practices. 확인 시 GPT-6 Astra 안내였다. API·실행 모델 교체 요청으로 해석하지 않았다.

공식 권고는 요청 범위 안에서 작업을 끝내고, 사용자 지시의 우선순위를 명시하며, 불필요한 확인과
과도한 반복 검증을 줄이는 것이다. 위임·출력 방식은 작업 환경에 맞춰 정한다.
아래 브랜치 시점은 공식 문서의 요구가 아니라 사용자가 정정한 프로젝트 정책이다.

| 대상 | 발견 / 조치 |
|---|---|
| AGENTS·BRANCHING·README·IMPLEMENTATION·HARNESS·ADR | 준비에도 분기하는 문구를 실제 구현 착수로 제한. 공통 우선순위·질문·검증·출력 원칙을 AGENTS에 모음 |
| poke-implement | 준비 요청에 구현 절차를 적용하지 않도록 명시. 짧은 작업에 별도 양식 생성을 강제하지 않음 |
| poke-platform-review | 앱 검증 요청을 패키징 구현 허가로 해석하던 문구 수정. 잘못된 src/package.json 경로 표현 수정 |
| poke-verify | 필요한 QA 절만 읽고 통과 후 반복·확대 조건 명시. 검증만으로 브랜치를 만들지 않음 |
| poke-art-ux | 작업별 참조 분리, 준비 문서 변경과 실제 UI 검증 구분, 외부 역할 문구 적용 범위 명시 |
| frontend-design | 전체 검토. 가상 고객 설정·확인 지시가 프로젝트 맥락에 우선하지 않도록 호출 스킬에서 제한. 고정 원문·LICENSE·해시는 보존 |

전역·다른 프로젝트 스킬은 수정하지 않았다. 외부 스킬 원문을 바꾸지 않고 프로젝트 적용 지점을 수정했다.
게임 규칙·에셋·API 의존성·모델 설정은 변경하지 않았다.

## 검토 시나리오

문서 대조로 확인한 사례이며 독립 에이전트 실행 평가를 했다는 뜻은 아니다.

- 환경 준비 요청: main 유지, 환경 지침만 수정, 게임 구현과 브랜치 생성 없음.
- M1-01 구현 요청: 보존할 변경 확인 후 실제 구현 브랜치 생성, 관련 입력 회귀와 필수 check.
- 앱 전환 가능성 검토: 읽기·증거 분석, 앱 미구현이면 명시, SDK 추가 없음.
- 화면 수정: 기존 제품·토큰 활용, 별도 형식적 승인 없이 구현·화면 검증.
- 지침만 수정: 링크·스킬 구조·필수 check, UI E2E 재실행을 자동 요구하지 않음.

## 디자인 논의 구분 보완

후속 사용자 합의로, 불필요한 재승인 방지는 미선정 디자인 방향의 논의를 생략하라는 뜻이 아님을 명확히 했다.
DESIGN_WORKFLOW와 DESIGN_DECISIONS를 기준으로 시안·추천·선택·검증을 인계한다.
