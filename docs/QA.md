# 검증 전략과 출시 게이트

requirements.json이 원본 절과 검증 방법의 연결표다.
파일 존재 검사, 기준 로직 테스트, 제품 통합 테스트, 실제 연출 검수, 실기기 성능, 재미를 별개로 보고한다.

## 자동 검증 계층

| 계층 | M0 제공 | 이후 추가할 검증 |
|---|---|---|
| 프로젝트 무결성 | 필수 파일·로컬 링크·ID·콘텐츠 계획 호환성 | runtime 자산·번역 키·manifest |
| 단위 | 점수·반올림·경계·실패 순서·콤보·시계·좌표 | 입력 해제·seed stream·bag·selection·storage |
| 재현 | 확정 입력과 월드 배치 10개 fixture | 초기 프로필·시드·시간 입력·결말·백 전체 재현 |
| 브라우저 | Chromium 데스크톱/360px 준비 화면·실제 JS·콘솔/404 | 전체 게임·언어·설정·복귀·스킵·도감 |
| 빌드 | 타입 검사, Vite dist, CI 구성 | production 디버그 미노출·전송 예산·배포 URL |

실패 경계 649/650/699/700, 최고 파워 비명중, 0 파워 접촉, d=1, 0.85 전후를 회귀에 포함한다.
캐릭터·프로필·연출 선택을 바꿔도 판정이 같은지 통합 테스트를 추가한다.
초기화·저장·백 소비·종료가 한 번씩만 발생하는지를 테스트한다.

## 제품 브라우저 시나리오

1. Pointer tap 2회 / Space·Enter 2회. 첫 입력 유지·repeat·멀티터치·click 합성 이벤트로 발사되지 않음.
2. 60%를 고정해도 AIM 유지, 새 입력으로 즉시 발사. 정중앙과 비명중의 원인·장면이 다름.
3. 699 실패/700 성공, 판정 점수와 콤보 획득 점수 구분, 실패는 런 점수 추가 없음.
4. 조작 중 언어·음소거·설정을 바꿔도 시계·상대·파워 유지, 조작 이벤트 전파 없음.
5. 숨김·blur·잠금 이후 게이지·연출 점프 없이 재개 버튼을 통해 이어감.
6. 실패의 핵심 장면 뒤 게임오버, 스킵 입력이 재도전까지 연쇄 실행되지 않음.
7. 8종 백 소진과 경계·재도전·리로드, 준비 에셋 실패 뒤 동일 후보 1회 소비.
8. unlocked와 seen 차이, 최소화·도감 프리뷰·멱등 종료·이전 roundId 콜백 무시.
9. 저장 접근 거부·손상·미래 스키마·오디오 resume 거절·WebGL 실패·context loss·에셋 실패.
10. 개발 디버그 기능이 dist에서 노출되지 않음, 자산 404·HTML 오응답·치명적 콘솔 오류 없음.

## 실기기 및 수동 검증

| 환경 | 확인 | M0 상태 |
|---|---|---|
| Windows Chromium | 준비 화면 모듈 및 오류 smoke | STATUS 기록 |
| Chromium 360×800 에뮬레이션 | 준비 화면 가로 넘침 | STATUS 기록 |
| Android Chrome 실기기 | 터치·주소창·회전·오디오·fps | 미실행 |
| Samsung Internet 실기기 | 위 항목과 복귀·저장 | 미실행 |
| iOS Safari 실기기 | 노치·홈 영역·오디오 시작·잠금·WebGL 복구 | 미실행 |
| 키보드·스크린리더 | 포커스·이름·단계/결과 알림·무음 | 제품 미구현 |

WebKit 자동화는 Safari 엔진 회귀 보조이며 실제 iPhone 성능 증거가 아니다.
공개 전 정체 단서, 패드와 장갑 끝점, 비명중에 피격 반응 없음, 소켓 수갑 위치는 영상으로 확인한다.
움직임 감소·흔들림 OFF에서도 점수·반전 이해가 가능한지 검수한다.

## 성능 측정

초기 목표: 주요 모바일 60fps, 저사양 약 30fps에서도 판정 유지.
모바일 DPR cap 1.5, 데스크톱 2; 조준 드로콜 <=100, 화면 삼각형 약 100,000,
최초 플레이까지 압축 전송량 약 5MB 이하.
모두 목표이며 아직 게임 성능을 측정하지 않았다.

측정 로그에 날짜, 커밋, 실제 기기·OS·브라우저, 화면·DPR·품질 설정,
콜드/웜 캐시, 네트워크 조건, 구간 길이와 도구를 적는다.
조준·발사·공개·대표 결말별 프레임 시간 p50/p95, renderer.info, 전송 합계를 기록한다.
재도전 반복 전후 메모리·리스너·렌더러 수를 비교해 누수 징후를 확인한다.
초과 시 측정값·원인·개선·재측정 결과를 남긴다. 준비 화면 번들 크기로 게임 5MB 충족을 주장하지 않는다.

## 플레이 테스트

templates/PLAYTEST.md를 사용한다. 소수 참가자를 시작점으로 삼고 실제 표본을 명시한다.
관찰 질문: 실패 후 다시 하는가, 실제 원인을 이해하는가, 반복 결말을 지루해하는가,
다른 실패 유형을 시도하는가, 저파워 반복은 수집 탐색인가 조작 포기인가.
실패 종료 후 재도전 수/해당 실패 수, 새 결말과 반복 결말의 스킵 수/기회 수를 구분한다.
본편 길이·스킵 설정·환경을 함께 적고 임의 점수나 모집하지 않은 참가자를 쓰지 않는다.
초기에는 로컬 익명 세션 로그로 충분하다. 외부 분석 SDK·서버를 전제하지 않는다.

## 출시 게이트

- R-LOOP부터 R-ASSETS까지 해당 제품 수용 기준과 증거가 채워짐.
- check와 제품 E2E 통과, 실제 지원 대상 환경의 미검증·알려진 제한을 명시.
- 8종·5계열·대표 난투·수갑·성공 반응을 연속 영상으로 검수.
- 입력·공정성·저장·스킵·복구 결함 없음, 성능 예산 실측 및 초과 조치 기록.
- 실제 플레이 테스트의 관찰 결과를 반영. 기능 통과와 재미 판단을 별도 승인.
- 에셋 출처 확인, Vercel 실제 URL과 새로고침·자산 응답 검증.

M0의 check 성공은 이 출시 게이트의 통과를 의미하지 않는다.
