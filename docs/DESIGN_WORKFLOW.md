# 에셋·UI·UX 제작 하니스

## 도구 선택과 현재 준비 상태

| 작업 | 사용할 도구·스킬 | 현재 상태 |
|---|---|---|
| 화면 구성·타이포·색·시각적 위계 | Anthropic frontend-design + poke-art-ux | 저장소 설치 |
| 콘셉트·텍스처·래스터 이미지 | 내장 imagegen 스킬과 이미지 생성 도구 | 현재 세션에서 사용 가능, 별도 API 키 불필요 |
| 게이지·아이콘·말풍선 | HTML/CSS/SVG 소스 | 기본 스택으로 제작 |
| 실제 전신 모델·리그·소켓·타임라인 | Three.js + CONTENT 계약 | 제작 예정; 콘셉트 이미지와 구분 |
| 화면·조작 회귀 | Playwright + poke-verify | Chromium smoke 구성·기존 검증 완료 |
| Figma 디자인 파일 반입·협업 | Figma 플러그인 | 미설치·미연결; 실제 파일 기반 작업을 택하면 연결 |
| 외부 3D·음원 제작 서비스 | 특정 서비스 미선정 | 제작 필요·내보내기 형식·라이선스 확인 후 선택 |

추가 유료 서비스나 계정 연결은 현재 하니스의 필수 조건이 아니다.
이미지 생성 도구가 없는 다른 환경에서는 해당 기능을 사용 가능하다고 주장하지 않는다.
Figma 설치·연결과 도구 호출 확인 전에는 Figma 파일을 읽었다고 기록하지 않는다.

## 외부 스킬 출처와 적용 범위

frontend-design은 [공식 저장소](https://github.com/anthropics/skills/tree/34040c9c568585f6929bedeaad110ad08f079624/skills/frontend-design)의
Apache-2.0 배포본을 원문 그대로 설치했다. 커밋·파일 해시는 external-skills.json에 기록한다.
설치 스킬은 다음 턴부터 목록에서 사용할 수 있으며, 목록에 없으면 AGENTS의 링크로 직접 읽는다.
외부 스킬의 일반 웹사이트·hero 섹션 조언은 이 게임의 즉시 플레이 화면에 맞춰 적용한다.
가상 고객 역할·제안 거절 서술을 실제 이력으로 취급하지 않는다. 이미 확정한 제품 결정을 반복 승인받지 않되, 아직 정하지 않은 시각 방향은 아래 과정으로 사용자와 결정한다.
현재 제품의 화면·표현·성공 기준과 Vite/TypeScript/Three.js 경계가 우선이다.
React·Tailwind·폰트 CDN·대형 랜딩페이지를 외부 스킬만을 이유로 추가하지 않는다.

Vercel web-design-guidelines도 검토했지만 확인 커밋의 루트와 스킬 경로에서 라이선스 고지를 찾지 못해
저장소 복사 설치는 보류했다. 이는 사용 불가라는 법적 판단이 아니라 이번 재배포 선정 기준이다.
검토 출처: [스킬](https://github.com/vercel-labs/agent-skills/tree/063bee94c3f4df8453406c830b0a7df0f2860278/skills/web-design-guidelines).

외부 스킬 업데이트는 자동으로 main 최신본을 덮어쓰지 않는다. 새 커밋의 내용·고지·참조를 검토하고
같은 작업 PR에서 설치본과 external-skills.json 해시를 갱신한 뒤 check를 실행한다.
이 스킬은 개발 보조 자료이며 게임 런타임 번들에 포함하지 않는다.

## 디자인 진행과 의사결정

이 절은 새 세션·다른 작업자에게도 적용한다. 현재 합의한 것은 진행 방식이며 시각 스타일의 선택은 아직 아니다.
사용자의 질문·의견 요청에는 설명으로 답한다. 조사·시안 제작·구현은 해당 작업을 요청받은 범위에서 수행한다.
현재 환경 준비는 main에서 유지한다. 실제 제품 구현 착수 시에만 BRANCHING의 분기 절차를 적용한다.

| 순서 | 작업자가 준비할 결과 | 다음 단계 기준 |
|---|---|---|
| 1. 레퍼런스 조사 | 유사 게임의 조작 안내·실패 피드백·반전 타이밍·캐릭터 식별·재도전 분석 | 출처와 관찰 근거, 적용할 점·적용하지 않을 점을 설명 |
| 2. 방향 시안 | 같은 조준·결과 장면으로 비교하는 2~3개 스타일, 장단점과 추천안 | 사용자와 전체 분위기·코미디 수위·선호 방향 결정 |
| 3. 대표 캐릭터와 화면 | 대표 1~2명의 정면·측면·후면·표정·주요 포즈 시트, 장갑·패드, 실제 크기의 화면 구성 | 캐릭터와 화면이 함께 성립하는지 검수 |
| 4. 짧은 플레이 검증 | 조준→발사→공개·반응→재도전의 실제 동작 | 이해도·연출·조작을 관찰하고 수정, 확장 여부 결정 |
| 5. 콘텐츠 확장 | 확정 토큰·리그·연출 기준으로 나머지 캐릭터·화면 제작 | 기존 QA와 요구사항별 증거 충족 |

대표 캐릭터는 M1의 철근 씨·민원 여왕을 우선 후보로 삼는다. 8명 전체 시트를 먼저 완성하지 않는다.
시트는 성인 체형·동일 인물 일관성·실루엣을 확인하고, 조준 화면에서는 정체 은폐를 별도로 확인한다.
콘셉트 시트는 실제 메시·리그의 완성이 아니다. 움직임·카메라·모바일 가독성은 플레이 검증으로 확인한다.
기존 CONTENT의 색·재질 방향은 출발점이다. 명세와 충돌하는 후보는 충돌을 명시하고 임의 채택하지 않는다.

## 판단 책임과 사용자 참여

작업자는 가독성·정보 위계·일관성·접근성·제작 난도·모바일 예산을 평가하고 근거 있는 추천안을 제시한다.
사용자에게 디자인 전문 지식이나 세부 기술 평가를 요구하지 않는다.
방향 선택은 실제 시안과 함께 “어느 분위기가 원하는 게임에 가까운가”, “어떤 반응이 재미있거나 불편한가”처럼 묻는다.
추천 이유와 각 선택이 바꾸는 경험을 설명하며, 설명 없이 “마음에 드는 것을 고르라”고 맡기지 않는다.

처음 시각 방향을 정할 때와 짧은 플레이 검증 후 대량 확장 전에 미결된 제품·취향 선택을 확인한다.
사용자가 이미 선택했거나 해당 판단을 명시적으로 위임했다면 그 범위에서 진행하고 반복 확인하지 않는다.
답변이 필요한 선택은 침묵을 동의로 간주하지 않는다. 그 선택에 의존하지 않는 허용된 작업은 계속한다.
간격·정렬·버그 수정 등 확정 방향 안의 세부 조정은 작업자가 처리한다.
자동 테스트와 작업자의 미적 평가만으로 재미를 확정하지 않는다. 실제 플레이 관찰로 이해도·재도전·불편함을 확인한다.

## 인계와 증거

디자인 작업 시작 시 [현재 결정 기록](DESIGN_DECISIONS.md)을 먼저 확인한다.
[디자인 양식](templates/DESIGN.md)으로 출처·관찰 장면·시안 파일·추천 이유·사용자 선택을 남기고 현재 결정 기록에 연결한다.
조사에서 본 사실과 작업자의 해석을 구분한다. 공식 소개 페이지 조회만으로 영상을 보거나 직접 플레이했다고 하지 않는다.
레퍼런스의 캐릭터·UI를 그대로 복제하지 않는다. 새 세션에서 비교에 필요한 시안은 임시 경로에만 남기지 않고
작업자가 접근할 수 있는 프로젝트 경로에 보관한다. 외부 이미지의 재배포 조건이 불명확하면 출처·장면 위치를 기록한다.
선택 대기 / 채택 / 수정 필요를 구분하고 날짜·근거·위임 범위·남은 질문·다음 허용 작업을 갱신한다.
새 작업자는 채택한 결정을 이어받고, 변경이 필요한 근거가 있을 때만 재논의한다.

## UI·UX 수용 기준

- POWER/AIM의 현재 행동이 구분되고 패드·장갑·게이지·주 버튼이 서로 가리지 않는다.
- 실패 원인과 재도전이 이해되고, 연출·스킵 입력이 다음 행동까지 전파되지 않는다.
- 처음에는 정체가 숨겨지고, 공개는 같은 전신 캐릭터의 연속 동작이다.
- KO/EN 긴 문구, 360px·가로·safe-area, 보조 터치 44px·주 액션 약 64px 목표를 검수한다.
- 키보드 포커스·접근성 이름·색 이외 단서·무음 이해·움직임 감소를 확인한다.
- 메뉴·조준·공개·결과·도감·중지·로딩 실패의 상태별 누락을 확인한다.
- 화면 캡처의 기기/뷰포트·언어·상태를 기록한다. 실기기 성능과 재미는 별도 관찰로 남긴다.

## 에셋 반입 기준

[에셋 작업 양식](templates/ASSET.md)과 ASSET_LICENSES에 실제 파일·저작자·원본·조건·수정 내용을 기록한다.
AI 생성물은 도구·날짜·최종 프롬프트·참고 이미지 출처도 기록한다. 생성했다는 이유로 CC0를 부여하지 않는다.
선정 전 이미지는 artifacts/local에서 검토하고, 실제 채택한 파일만 프로젝트의 최종 경로로 복사한다.

| 종류 | 검수할 내용 |
|---|---|
| 전신 3D | 성인 비율, 동일 리그, 패드 좌표, 장갑 끝점·소품 소켓, 공개 전 정체 단서, dispose 소유권 |
| 텍스처·래스터 | 실제 크기, 투명 가장자리, 색 공간·용도, 용량, 모바일에서의 가독성 |
| SVG·폰트 | 편집 소스, 읽을 수 있는 작은 크기, 한국어 글리프, 폰트 라이선스·번들 용량 |
| 음원 | 출처·조건, 길이·음량, 루프 경계, 첫 입력 후 재생, 현실적 비명·타격음 배제 |

텍스트 번역은 이미지 안에 굽지 않고 i18n/UI에서 처리한다. AI 이미지를 GLB·리깅 완료로 간주하지 않는다.
성능 예산은 QA의 기존 목표를 따른다. 현재 하니스는 새로운 게임 에셋을 제작·확보하지 않는다.
