# 웹·앱 전환 검토

[AGENTS](../../../AGENTS.md)의 요청 범위를 따른다.
[플랫폼 경계](../../../docs/PLATFORMS.md), [아키텍처](../../../docs/ARCHITECTURE.md)의 관련 절과 src 코드·루트 package.json을 대조한다.
검토에 필요한 측정 기준만 [QA](../../../docs/QA.md)에서 읽는다.

- 구현된 기능과 설계만 존재하는 기능을 분리한다. 재사용 가능한 게임 코어와 플랫폼 의존 호출 위치를 제시한다.
- 저장 어댑터의 비동기 계약, 프로필 마이그레이션, 웹→앱 기록 이전의 필요 여부를 확인한다.
- pause/resume, 오디오 복귀, WebGL context loss, 뒤로가기, safe-area와 번들 에셋을 검토한다.
- 준비·가능성 검토는 현재 증거와 필요한 후속 작업을 보고한다.
  실제 패키징 구현을 요청받았을 때만 구현 브랜치와 ADR을 준비해 요청한 실험을 수행한다.
  기존 앱 검증 요청이면 해당 앱을 검사하고, 앱이 없으면 미구현으로 보고한다.
- 성능은 조준·발사·공개·결말별 실측으로 판단한다. WebView 패키징을 네이티브 렌더러 전환으로 설명하지 않는다.
- 마켓 제출 검토 시 공식 정책을 새로 확인한다. 명칭·실제 동작·음향·스토어 이미지와 성인 쇼 설정의 일치를 검토한다.
  설정 문구나 기술 호환성만으로 심사 승인을 보장하지 않는다.

결과는 현재 가능 범위, 필요한 변경, 미검증 게이트로 나누어 제시한다.
read-only 검토이면 파일 수정 없이 보고한다. 게임 규칙 변경이나 서버·결제 추가는 독립 제품 결정이다.
