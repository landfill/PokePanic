# 게임 아트와 조작 경험

[AGENTS](../../../AGENTS.md)를 따른다. 화면 작업은 [PRODUCT](../../../docs/PRODUCT.md),
에셋 작업은 [CONTENT](../../../docs/CONTENT.md)의 해당 절을 읽는다.
도구·반입 절차는 [제작 하니스](../../../docs/DESIGN_WORKFLOW.md)를 참조한다. 기존 화면·토큰을 먼저 확인한다.

화면을 새로 설계하거나 개선할 때 [frontend-design](../frontend-design/SKILL.md)을 함께 적용한다.
frontend-design의 가상 고객·과거 제안 거절 서술은 실제 사용자 이력으로 취급하지 않는다.
이미 확정한 제품 결정을 반복 승인받지 않는다. 아직 미선정인 시각 방향은 사용자와 함께 결정한다.
시작 시 [현재 디자인 결정](../../../docs/DESIGN_DECISIONS.md)을 확인한다.
조사 → 2~3개 시안과 추천 → 대표 1~2명 시트·화면 → 짧은 플레이 검증 → 확장을 따른다.
자세한 산출물과 확인 시점은 제작 하니스의 디자인 진행·판단 책임 절을 적용한다.
사용자는 경험·취향을 판단하고 작업자는 가독성·접근성·일관성·제작 가능성을 근거로 평가한다.
선택·위임·미결 사항과 시안 경로를 기록해 다음 작업자가 이어받게 한다.
질문에 대한 의견 요청을 조사·시안·구현 착수 허가로 해석하지 않는다.
일반 웹 hero·광고 카피보다 현재 게임의 플레이 공간·행동 명료성·정체 공개가 우선이다.
미학 선택으로 판정·실패 원인·터치 영역·스포일러 은폐를 훼손하지 않는다.

- 대상 상태·사용자 행동·요구사항을 먼저 고정하고 디자인 양식에 토큰과 배치를 기록한다.
- 콘셉트·텍스처 등 래스터 제작은 사용 가능한 imagegen 스킬과 도구를 사용한다.
  편집 가능한 SVG·게이지는 기존 소스로 제작한다. 전신 메시·리그는 실제 Three.js 자산으로 검증한다.
- 캐릭터 참고 이미지는 동일 인물의 실루엣·의상·재질·정면/후면 일관성을 지정한다.
  가상 성인 배우·폼 장갑·외부 보호패드·촬영장 표현을 유지한다.
- 참고용 생성물과 제품 채택물을 구분한다. 실제 채택 파일은 프로젝트 안에 저장하고
  ASSET_LICENSES에 출처·조건·프롬프트·편집 원본을 남긴다. 에셋 양식을 사용한다.
- 실제 UI는 KO/EN과 360px 세로·가로에서 확인한다. POWER/AIM, 결과와 재도전,
  스킵·도감·중지·오류의 동작 및 초점·무음·움직임 감소를 검수한다.
- 실제 UI 변경은 브라우저 캡처·관련 E2E로 검증한다. 준비 문서만 바뀌면 UI 검증은 추가하지 않는다. 저장소 변경 후 필수 check를 수행한다.
  보이는 품질, 기능 통과, 실기기 성능, 재미 결과를 구분한다.

준비만 요청받으면 실제 게임 화면·이미지를 임의로 대량 생성하지 않는다.
Figma 등 외부 서비스는 실제 자료 접근이 필요하고 연결이 확인되었을 때 사용한다.
